### 정한 것

- `[정함]` **일정 — 2026-10-28 후원주점에서 시제품 공개, 정식 출시는 2027년 초** (사용자, 2026-10-13).
  사용자: 「못하면 못하는 거지」 — 날짜에 맞추려고 기획을 줄이지 않습니다.
- `[정함]` **가장 중요한 것 — 관계, 그리고 다시 들어올 명분** (사용자, 2026-10-13).
  「마을이 포인트가 아니라 관계를 중시하고 들어올 명분이 있게 만드는 게 제일 중요」.
  기능을 고를 때 이 둘로 잽니다 — 이것이 누구와의(무엇과의) 관계를 만드나, 다시 올 이유가 되나.
- `[정함]` **이 게임은 회원확대 전략의 「문」 하나** (사용자, 2026-10-15 「ㅇㅇ 그렇지, 결국 그 방향으로」). 전략 원문은 local-finance 기록
  「2026-10-08 — 재정플랫폼과 2027년 신규 후원자 1,000명 전략」(시민의 길·여러 개의 문·월 1회 소식·1~3차 전화·독상 시민 선택·현장 투어·공개 보고회).
  게임의 몫 = **재미로 처음 만나게 → 연락처 → 현장으로 초대**. 10-08 의 「예산게임과 엮지 말 것」 은 이것으로 바뀌었다(사용자가 직접 이음).
- `[정함]` **맨 위의 목적 — 단체를 응원하고 함께하고 싶게** (사용자, 2026-10-15). 이용자가 느껴야 할 만족감 둘:
  ① 「내가 할 수 없지만 해야 한다고 생각하는 일을 이 단체가 하고 있어」(→ 응원·후원) ② 「이 단체랑 뭔가를 하면 활력이 도네」(→ 함께하기).
  **기능을 고를 때 묻는 두 질문** — 이걸 하고 나면 「시민행동이 내 대신 해 주는구나」 를 느끼나? 「같이 하니 신난다」 를 느끼나? 둘 다 아니면 덜어 낸다.
  아래 「재미있고 유익하고 후원하고 싶게」(10-13)·「관계와 다시 올 이유」 는 이 목적을 위한 수단이다.
  계기: Claude 가 앱 문법(동전·매일 부탁·재방문 장치)으로 짜서 단체가 안 보였다 — 사용자 「시민단체의 정체성을 어떻게 살리면서 할지」 「본질적인 대답이 아니다」.
  게임 회사는 사람을 붙잡아 두고, 시민단체는 사람을 현실의 행동으로 내보내고 그 결과를 돌려준다.
- `[정함]` **오프라인 접점 — 방향만, 아직 안 만듦** (사용자, 2026-10-15 「예산은 숫자로만 이뤄져 접점이 부족, 지금은 이쁜 웹사이트랑 다를 게 없다」 → 「다 좋아, 기록해 둬」).
  예산은 숫자지만 예산이 만든 것은 동네에 서 있다 — 그 현장에 같이 가 본다. 화면 속 걷기는 진짜 동네를 같이 걷는 일의 예행연습.
  **고리: 화면에서 초대 → 현장에서 같이 → 화면에 기록(그 뒤 이야기·현장 도장) → 다음 초대.** 게임의 몫은 초대와 기록뿐.
  접점 — ① 예산 산책(그달 문제 카드 현장을 같이 걸어 보기) ② 우리 동네 모임(시·군·구에 사람이 모이면 「○○구 모여봐요」) ③ 예산철 현장(의회 방청·독상 시상식·후원주점) ④ 회원에게 종이 엽서(이달의 문제 카드 + QR).
  걸리는 것: 활동가가 한 달에 한 번 현장을 꾸려야 돈다.
- `[정함]` **모인 답은 어디에 쓰지 않는다 — 게임은 회원 유입용** (사용자, 2026-10-14: 「이건 어디에 쓸 게 아님.
  걍 회원 유입용임」). 10-13 의 「내 선택이 모여 쓰인다는 명분」 을 이것으로 바꿨습니다. 그래서 「12월 발표」·「의견서」
  같은 약속을 게임에 넣지 않습니다. 얻어 갈 것은 **내 성향과 남들 생각**, 그리고 **관계·계속 참여할 거리**입니다.

링크 받기 ⚠️(보낼 문구 없음) → 걷기·결과 ✅ → 결과를 단톡방에 ✅(`?with=`) → 문제 카드 반응 ✅(서버 판) → 예산 산책 신청 ❌ → 산책·현장 도장 ⚠️(도장만) → 「그 뒤 이야기」 알림 ❌ → 구독자는 후원 권유·후원자는 감사 ❌

**가설 B — 단톡방에서 친구 링크로 온 새 사람(지인)**
링크 열기 ✅(카톡 카드·「○○님이 불렀어요」) → 걷기·결과·친구와 나란히 ✅ → 마을 입구 로그인 ⚠️(키 없음, 해도 연락처는 안 남음) → 문제 카드 반응 ✅ → **소식 받기(연락처) ❌ 공개판에 없음** → 월 1회 소식 ❌ → 산책 초대 ❌ → 1~3차 전화 ❌

**가설 C — 행사장 테이블 QR(현장)**
테이블에서 같이 걷기 ❌(10-26 기능째 걷음 — 시트 서버가 4초마다 묻는 걸 못 버텨 켤 수 없었다) → 각자 걷기·결과 ✅ → 현장 도장 ✅(기기에만) → 연락처 ❌ → 다음 행사 초대 ❌

**가설 E — 동네 커뮤니티에서 문제 카드를 본 그 동네 주민(일반 시민)** (사용자 10-15 「일반 시민들 가설은 애매한가?」 — 1,000명엔 가장 중요한 길)
단체를 모르는 주민이 동네 단톡방·지역 커뮤니티에 돈 카드 링크(`?card=`)로 → 카드 먼저 ✅ → 반응 ✅ → 연락처 ❌ → (걷기는 할 수도, 안 할 수도)
새 구멍: 카드 공유가 눈에 안 띈다(카톡 미리보기 늘 같은 그림) · 누가 만든 카드인지 모른다(단체 한 줄) · 연락처를 카드에서 받아야 한다 · 카드가 여러 동네에 있어야 한다(활동가 부담).
지역 커뮤니티는 홍보 글을 막는 곳이 많아 주민이 스스로 퍼 날라야 돈다 [추측].

**가설 F — 아이가 있는 부모** (사용자 10-17 「후원 타겟 중 하나를 아이가 있는 부모로. 아이한테 도움이 되어야 엄마가 후원하지」. 선생님이 수업자료로 써도 된다)
아이가 마을 부탁·오락실로 예산을 놀이로 익힌다 → 부모가 그걸 본다 → 후원. **아동용·성인용으로 나누지 않는다 — 어른도 아이도 재미있는 게임 하나**(학년 대신 단계로 어려워진다).
만 14세 미만은 따로 만들지 않는다(사용자 「알아서 들어오겠지」). 「예산 탐정 증명서」 같은 건 만들지 않는다. 부모·아이 묶기·가족 기록은 뺐다(사용자 10-17 「가족 친구 기록은 일단 없애고」).

**빈 구멍 — 막는 길이 많은 순**
1. **연락처 받는 곳이 공개판에 없다**(A·B·C) — 화면·동의는 있고 개발판에서만 켜짐(`contactReady`). 켜려면 보유 기간·개인정보처리방침 한 줄. 받을 자리(문제 카드 반응 직후·산책 신청·끝 화면)도 정해야.
2. **로그인은 연락처가 아니다**(B) — 10-15 준비함: 로그인 때 확인된 이메일을 받아 바로 「소식 받기」 칸에 채운다(동의해야 남음, 아래 「로그인」). 키·`contactReady` 켜기 전이라 아직 공개판엔 없다.
3. **현장으로 가는 칸이 없다**(A·B·C) — 문제 카드에 「같이 보러 가요(날짜·장소)」 신청 칸(화면은 Claude), 산책 자체는 활동가.
   사용자 10-15: 「좋은 일이지만 엄청 부담스러운 일 — 신중하게」 → 먼저 하지 않는다.
4. **다시 부르는 길이 없다**(A·B) — 「그 뒤 이야기」 칸 + 월 1회 소식(스티비 꼭지).
5. **행사장에서 같이 하기가 안 된다**(C) — 테이블은 10-26 걷었다(시트 서버 폴링 한도로 켤 수 없었다). 현장에서 같이 하려면 다른 길을 새로.
6. **전화는 동의가 없다**(A·B) — 지금 동의는 이메일·문자 소식뿐. 1~3차 전화를 하려면 전화 권유 동의와 거는 사람이 따로 필요 [관리자 확인].
7. **어디서 와서 어디서 그만두는지 모른다**(전부) — 유입 꼬리표(UTM)와 공유·연락처 수를 안 잰다.
   (40~50대도 열다섯 방을 끝까지 걷는다는 것은 전제 — 사용자 10-15.)
- 서류(보유 기간·개인정보처리방침 한 줄·전화 권유 동의)는 다 할 수 있다(사용자 10-15) — 1·6 은 서류가 막는 구멍이 아니다.

### 설문 v4 — 축·용어·루트 `[초안]`

사용자: 「축을 일단 수정해 봐. 루트도 제대로 설계하고. 문항 평가·논의는 사람들이 해야 해서
기다려야 하지만, 일단 네 판단으로 해 봐 — 특히 용어. 용어는 눈으로 보고 고칠게.」
(2026-10-13). 그래서 **전부 Claude 판단의 초안**이고, 사람이 검토하면 `확정` 으로 바꿉니다.

**내용은 `game/content.ts` 한 파일에 있습니다.** 축 이름, 문항 문구, 짧은 이름(표지판용),
루트, 유형 이름이 다 거기 있습니다. 문구를 고칠 때는 그 파일만 고치고
`npm test` 의 `tests/game-content.test.mjs` 가 통과하는지 봅니다(루트·축·짧은 이름 길이·판정을 확인).
채점은 `game/score.ts`.

**① 세 축 — 예산게임(budget-mbti)의 편성 축과 같은 이름·같은 방향으로 맞췄다**

| 축 | 0 쪽 | 1 쪽 | 뜻 |
|---|---|---|---|
| 어디에 (`hands`) | 시설·제도 | 사람에게 | 모두가 쓰는 바탕을 만드나 / 사람에게 바로 닿나 |
| 언제 (`time`) | 당장 | 두고두고 | 올해 효과 / 몇 년 뒤부터 오래 |
| 누구에게 (`reach`) | 좁고 깊게 | 넓고 고르게 | 꼭 필요한 곳에 몰아서 / 많은 사람에게 고르게 |

왜 —
- **v3 의 「분배↔성장」 을 뺐다.** 문항이 「세금을 줄여 국민이 쓸 돈을 늘린다」, 「가진 쪽에서
  걷어 나눈다」 처럼 지지 정당대로 답하게 생겼다. 예산게임도 8월에 같은 축을 「예산 범주에서
  읽히지 않는다」 며 버리고 「시설·제도↔사람에게」 로 바꿨다. 예산을 **어디에 쓰나**는 진영 없이 물을 수 있다.
- **「점진적 미래설계↔적극적 미래설계」 를 「당장↔두고두고」 로.** 양쪽 다 「미래설계」 라 무엇이
  갈리는지 안 보였다. 뜻은 그대로다.
- **「선별↔보편」 을 「좁고 깊게↔넓고 고르게」 로.** 뜻은 그대로고, 무상급식 논쟁 이후 정치 색이
  묻은 낱말을 피했다. 양쪽 다 좋은 말로 들리게.
- **예산게임과 같은 말을 쓴다.** 두 사업이 한 세계의 말을 쓰면, 편성해 본 사람과 설문에 답한 사람을
  같은 축 위에서 볼 수 있다. 방향(0/1)도 예산게임에 맞췄다 — 그래서 v3 와 유형 코드의 뜻이 다르다.

**② 문항 짓는 규칙 — v3 의 가장 큰 문제(축이 섞임)를 막는 규칙**

1. **한 문항은 한 축만 움직인다.** 두 선택지가 나머지 두 축에서는 같은 자리에 있어야 한다.
   `content.ts` 의 `holds` 칸에 묶어 둔 축을 적는다. v3 는 「지금」 쪽에만 「어려운 사람」 이
   붙어서, 분배를 중시하는 사람이 저절로 「지금」 을 골랐다.
2. **양쪽 다 좋은 말.** 한쪽에만 「어려운」 「공정」 「낭비」 같은 무게 실린 낱말을 두지 않는다.
3. **진영 신호 금지.** 세금 감면·증세, 특정 정부·정당의 정책 이름을 쓰지 않는다.
4. **같은 돈을 두고 고른다.** 규모가 다른 두 일을 견주지 않는다.
5. **짧게.** 선택지 한 줄, 짧은 이름(표지판·버튼) 8자 안쪽.
6. **무게(weight)는 검증 전까지 모두 1.** v3 의 구분력 3~5 는 짐작이었다. 응답이 쌓이면 재서 고친다.

**③ 루트 — 문항이 나오는 길**

- **문항은 모두 유형(세 축) 판정을 위해서만 있다** (사용자, 2026-10-13). 판정과 상관없는 문항을
  섞지 않는다 — 한때 Claude 가 「철마다 바뀌는 문항」 을 넣었다가 사용자가 걷어냈다. 그렇게 하면
  철마다 판정 재료가 바뀌어 뼈대가 무너진다. **다시 들어올 명분은 설문 밖에서** 만든다.
- **15문항 = 공통 9 + 분야 6** — v3 와 같은 뼈대. 공통 9문항은 분야 없이 가치만(축마다 3개).
  분야 6문항은 실제 예산 항목으로(축마다 2개, 서로 다른 여섯 분야, 국방·외교 뺌).
- **구간 다섯 × 3문항, 구간마다 세 축이 하나씩.** 1·3·5 구간은 공통, 2·4 구간은 분야 문항.
  같은 축 문항은 최소 세 칸 떨어진다(비슷한 질문이 붙지 않게). **모두가 같은 순서**로 답한다.
- **중간에 기울기를 보여 주지 않는다.** 구간을 지날 때는 진행만 보여 준다 — 앞 답을 보면 뒤 답이 끌려간다.
- `[보류]` 갈림 — 끝나고 어느 축이 가운데(±20 안)면 그 축 「결정 문항」 을 하나 더 내는 것.
  처음엔 안 한다. 응답이 쌓여 「반반」 이 많으면 그때.

**⑤ 채점** — v3 와 같은 식. 답 1~6 → 문항 점수 -2~+2 → 축마다 무게 가중 평균 × 50 → -100~+100.
점수가 0 보다 크면 1, 아니면 0(0 은 왼쪽 — 예산게임과 같은 규칙. v3 는 0 을 오른쪽으로 셌다).

**⑥ 사람이 검토할 것** — 문항 15개가 정말 한 축만 재는지(`holds`), 낱말이 한쪽으로 기울지 않는지,
유형 이름. 그리고 v3 의 공통 문항 중 살릴 것이 있는지(v4 는 축이 바뀌어 새로 썼다).

### 판정과 맞물리는 곳 — 구현 규칙

여기를 틀리면 게임은 돌아도 **유형이 틀리게** 나옵니다.

- **답 형식** — `Record<문항 id, 1~6>` (`game/score.ts` 의 `Answers`).
  1 이 `a` 쪽으로 가장 강하게, 6 이 `b` 쪽으로 가장 강하게, 3·4 는
  「조금」. 게임에서 무엇으로 고르든 끝에는 이 숫자 하나가 됩니다.
- **왼쪽·오른쪽** — `shouldSwapSurveyOptions(sessionId, questionId)` 가 참이면
  화면 왼쪽이 `b` 입니다. 게임 공간의 왼쪽 길·오른쪽 길 같은 배치도 **이것을
  따릅니다.** 왼쪽으로 가는 버릇이 결과를 쏠리게 하지 않으려고 둔 장치입니다.
  변환은 `swapped ? 7 - 화면값 : 화면값`.
- **결과 계산** — `game/score.ts` 의 `scoreAnswers` → `typeCode`. 새로 계산하지 않습니다.
  문항·루트·유형은 `game/content.ts` 에서만 읽습니다.
- **응답 시간** — 문항이 **보인 순간**과 **답한 순간**을 지금처럼 기록해 둡니다
  (`SurveyTiming`, `buildResponseMeta`). 저장을 붙일 때 나중에 만들 수 없는 값입니다.
- 좌우 섞기·응답 시간 함수는 `game/survey-response.ts`(옛 설문에서 떠 온 것).

**기획 4차 — 마을 (사용자와 Claude, 2026-10-14)** — 사용자: 「이거 마을 형태로 해서, 기존 게임이 들어온다면 예산 게임으로 가면 안 되잖아.
약간 마을 같은 곳에서 나와서 기존 게임도 다시 해 보고, 도장·시민참여 상담소·밑 빠진 독상·로컬 파이낸스도 보고, 거기서 이야기도 나눌 수 있게」.
Claude 가 질문을 몰아 묻고(사용자 「질문 있으면 몰아서 줘」) 답을 받아 만들었다. 번호는 그때 질문 번호.

- `[정함]` **한 바퀴 → 언덕 → 마을.** 처음 온 사람은 지금처럼 바로 걷고, 언덕의 빛 아치를 걸어서 지나면(기획 5차) 마을 남쪽 문에 나타난다.
  **다시 온 사람은 걷지 않고 마을 광장에서 시작**(2ⓐ). 걸으러 온 링크(`?walk`·친구 초대 `?with`)면 걷기 화면. 시작 화면 작은 단추는 하나만(10-26 사용자 ⓑ) — 지난번 판이 있으면 「걷지 않고 마을로 가기」, 없으면 「내 시민증 불러오기」(둘이 같이 떠 겹쳐 보였다). 걷기 화면에서 불러와 지난번 판이 생기면 로그인 됐다는 판에서 「마을로 갈까요?」(`town.ts` openLoggedIn toVillage).
- `[정함]` **후원주점판 `?pub`**(10-26 사용자 확정) — 동네 입구·골목 여섯 문항만 걷는다(`pub.ts`, content.ts·score.ts 그대로). 게임 기록·로그인·시민증·동전·도장은 이 페이지 메모리에만 두고 새로 열면 사라진다(`useTemporaryStorage`); 응답·유입·공유도 서버에 남기지 않는다. 마을 입장: 창립행사 환영 → 시민센터 안내 → 동쪽 지방정부 예산·곳간·따져 볼 지방정부 → 서쪽 상담소·독상. 각 묶음의 한 말 상자에 건물마다 한 줄 — 말하는 사람은 시민센터 채연하, 글은 `main.ts` TOUR_LINE(사용자 10-26 확정, 따져 볼 지방정부 줄만 사용자 글). 「다음」을 눌러 옮겨 가고, 다른 판을 열면 안내를 취소해 카메라·조작을 복구한다. 화면 회전 때 안내 묶음을 다시 맞춘다. **등불은 광장에 계속 걸려 있다** — 움직임 줄이기면 처음부터 켜진 정지 모습. **시민증은 주점판에서 실제 발급되지 않는다**: 도장 조건(셋)을 그대로 지켜 0/4·발급 전·저장 단추 숨김을 확인했다. 발급 조건을 낮추거나 가짜 발급을 만들지 않았다. 그래서 시민센터 자리 말은 「오늘은 짧은 판이라 시민증이 나오지 않아요. 시민증을 받고 기록을 이어 가려면 시민행동 홈페이지에서 본편을 해 보세요.」 + 「홈페이지 가기」(action.or.kr, 새 창) — 둘러보기를 건너뛴 사람도 보게 시민센터 판의 로그인 자리에도 같은 말·단추(`town.ts` HubData.home) — 사용자 10-26 「본편은 홈페이지에 공개하고, 주점에선 짧게 하고 실제 로그인과 본편은 홈페이지로」. 홈 첫 칸·캠페인 화면·상단 메뉴에 시민의 숲을 넣는 코드는 `action-home-renewal` 이 준비해 둔다.
- `[정함]` **「기존 게임」 = 열다섯 동네 걷기**(1ⓐ) — 마을 **버스 정류장**에서 다시 걷는다(`?walk`). 예산게임(100조 나누기)은 넣지 않았다(「따로 둔다」 그대로).
- `[정함]` **창립행사 응원판 — 후원주점판에만, 새 판**(10-26 사용자 「주점판에만」「글 남기는 곳 만들어줘. 새로 판 세워서」) — 자리는 **시민참여 상담소로 가는 길**(사용자가 캐릭터를 세워 짚음): 동서 큰길 위, 광장 왼쪽 가로등 바로 왼쪽. 처음 세운 광장 오른쪽(정류장 길 동쪽)에서 옮겼다. 행사 페이지(event.action.or.kr) 「이 사업을 응원해요」 구글 폼 응답과 이 판에서 바로 적은 응원을 새것부터 함께 보인다. 세 사업 중 하나를 고르고 300자까지, **자르지 않고 다 보인다**(「길이는 다 보여줄거야」「세 사업 중 고름」). 로그인 없음, 같은 기기 1분에 한 번(행사장에서 세 사업을 다 응원할 수 있게 쪽지 10분보다 짧게). **쪽지판 「게임에 대해 한마디」는 그대로 따로 모으기만**(「응원 + 게임 의견 따로」 — 처음엔 쪽지판을 응원판으로 바꾸려다 사용자가 새 판으로 물림). 나도·신고는 없다(로그인 없는 판) — 숨기기는 시트에서: 바로 적은 응원은 쪽지 탭(출처 `cheer`) 숨김 칸, 폼 응원은 응답 시트 맨 오른쪽에 머리글 「숨김」 칸을 더해 아무거나. 규칙 `cheer.ts` · 판 `cheer-board.ts` · 폼 읽기 `server/gas.ts` readFormCheers.
- `[정함]` **크게, 자유롭게, 더 넣을 수 있게**(3) — 지도 1040×1500(폰 화면 서너 개), 카메라가 나를 따라간다. 건물은 `village.ts` 의 `PLACES` 에 한 줄 +
  그림(`draw.ts`)·판(`places.ts`)·여는 곳(`main.ts` 의 `openPlace`). 비워 둔 「빈 터」 엔 기획 5차에 「마을 금고」 가 섰다.
- `[정함]` **건물 일곱** — 주민센터(주민증·도장·방명록·우리 지역·이웃 편지 = 옛 공터의 도장 주민) · 시민행동 집(회원 되기·홈페이지) · 시민참여 상담소 ·
  나라살림 창고(지방재정) · 쪽지판 · 밑 빠진 독상 · 버스 정류장(+ 기획 5차의 마을 금고·마을 공사터). 문 앞에 닿으면 판이 열리고, 건물을 톡 치면 문 앞까지 걸어간다. 위 띠 주민 폰 → 「지도」 = 건물 목록(고르면 그 문 앞으로).

### 게임 뼈대 (Claude, 2026-10-13)

**왜 이렇게 짰나**
- **걷는 것이 곧 고르는 것.** 「누구에게 갈까」 가 조작입니다. GPT 판은 긴 길을 위로 밀며 걷고
  고르기는 위 카드에서 해서, 걷기가 빈 시간이었습니다(한 판 44초 중 28초가 위로 밀기).
- **방 단위**(옛 젤다·포켓몬 건물 안처럼). 폰 한 화면에 질문·두 사람·나·문이 다 보여 카메라를 쫓을 일이 없습니다.
- **따라오는 줄** — 「관계」 가 눈에 보이게, 끝 장면과 「내 이웃」 의 재료로. 주민 생김새는 문항 id + 화면 쪽으로 정해
  a·b(축)와 엮이지 않습니다 — 줄을 봐도 기울기는 드러나지 않습니다(설문 v4 ③).
- **표지판에 새 문구를 짓지 않았다.** 결과 문구 30개를 지어 넣으면 사람 검토를 안 거친 내용이 들어갑니다.
  축 그림(시설/사람 같은)도 안 붙였습니다 — 중간에 기울기를 보여 주는 셈이라서.
- **다른 사람들 마음은 끝에서만, 다섯 명이 넘어야.** 중간에 보여 주면 뒤 답이 끌려가고, 두세 명 비율은 뜻이 없습니다.
- **조작** — 꾹 누르면 손가락 쪽으로(디아블로식), 톡 치면 거기까지. 말풍선·문 단추를 누르면 그리로 걸어가서
  키보드·화면 읽기 도구로도 끝까지 할 수 있습니다. 컴퓨터는 방향키·WASD·마우스.
- **문이 열렸을 때 벽에 붙어 위로 밀면 문 쪽으로 미끄러집니다.** GPT 판에서 출구 옆에 걸리던 자리입니다(시험 있음).
- `[정함]` 게임 이름 「함께해요 시민의 숲」(사용자 10-16 — 구글 로그인 앱 이름과 맞춤. 그 전 「모여봐요」(10-15)·Claude 임시 「동네 한 바퀴」 — 시트 서버 이름은 그대로 둠). 안내 문구, 버스·표지판 같은 물건은 Claude 가 붙인 임시입니다.

**고칠 때 걸리는 것**
- **`@keyframes` 안에 `calc(%…)` 를 쓰지 말 것**(아이패드 사파리가 안 돌림) — `%` 는 `translate` 속성으로 빼고 `@keyframes` 는 px 만. **한 규칙에 `translate` 와 `transform` 을 같이 두지 말 것** — 빌드 압축(lightningcss)이 `translate` 를 지운다(개발판은 멀쩡, 공개판에서만 깨짐).
- 마우스로 하는 PC(`pointer: fine`)는 화면이 1배여도 2배로 그린다(`main.ts` measure) — 그림·글씨·공유 그림 바탕이 또렷. 폰은 기기 배수 그대로.
- **캔버스 글씨는 `resolution: textRes(…)`**(`draw.ts`, 적어도 2배) — dpr 그대로면 PC 1배·윈도 125% 에서 뭉갠다. 시험 game-village 「캔버스 글씨」 가 막는다.
- 간판은 건물 그림에 구워 넣는다 — 주아가 늦게 오면 `draw.ts` 가 글씨 든 그림을 다시 굽는다. 간판에 새 글자를 쓰면 `CANVAS_TEXT` 에도 넣는다(개발판 콘솔이 알림).
- 플레이라이트 `screenshot` 은 글꼴을 기다렸다 찍는다 — 「글꼴 오기 전」 은 CDP `Page.captureScreenshot` 으로.
